# Security audit 2026-11-10

## Summary
First audit on record (no previous report to compare). The baseline from `20261011_security_rls.sql` holds: RLS is on for all 31 public tables, private columns on `student_jobs`, `hagwon_requests` and `teachers` are not readable by anon/authenticated, and both protect triggers are enabled. The most serious finding is that five tables that exist live but in no migration (`expedite_payments`, `payouts`, `purchases`, `resources`, `blog_posts`) have policies that let anonymous users insert or update rows. This PR adds a migration to close them, removes subscriber emails from a public API response, and clears all critical and 6 of 7 high npm advisories.

## Fixed in this PR
- `app/api/notify-subscribers/route.js`: the public route returned every subscriber's email address in its JSON response. Any visitor could create a request, then call the route within 10 minutes and read all subscriber emails. It now returns only counts. It also no longer returns raw error messages.
- `app/api/cron/daily-digest/route.js`: reject all calls when `CRON_SECRET` is unset (before, `Authorization: Bearer undefined` would pass).
- `next.config.js`: added `X-Content-Type-Options`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy` and `Permissions-Policy` (camera, microphone and geolocation off; no page uses them).
- `package-lock.json`: `npm audit fix` (no `--force`, `package.json` unchanged). Next 15.5.12 to 15.5.29; also fast-xml-parser, js-yaml, lodash-es, nanoid, sharp, source-map-js and ws. Build passes.
- `supabase/migrations/20261110_security_audit.sql` (not run): see findings below. Code check: no file on main references these five tables, so dropping their policies cannot break main.

## Findings (not fixed)
### Critical
- `expedite_payments`: `allow_insert`, `allow_select_all`, `allow_update_all` grant anon full read, insert and update (RLS true). Anyone can read payment rows and mark payments completed. Proposed fix: in the migration.
- `payouts`, `purchases`, `resources`: `server_insert` (insert, true) and `server_update` (update, true) apply to role `public`, so anon can create and edit payouts, purchases (`status`, `payment_key`) and resources (`price_krw`, `file_key`, `status`). Proposed fix: in the migration (drop; the service role bypasses RLS).
### High
- `blog_posts`: anyone can insert rows and update any column of any row. Nothing on main uses the table. Proposed fix: in the migration.
- These five tables are not in any migration on main (drift). Proposed fix: add them to the baseline once the open PRs land.
### Medium
- No `Content-Security-Policy` on the live site. Suggested report-only start: `Content-Security-Policy-Report-Only: default-src 'self'; img-src 'self' data: https:; script-src 'self' 'unsafe-inline' https://js.tosspayments.com; style-src 'self' 'unsafe-inline'; connect-src 'self' https://*.supabase.co; frame-ancestors 'self'`. Test before enforcing.
- `anon` and `authenticated` hold TRUNCATE, DELETE and TRIGGER on several tables (RLS blocks it today). Migration revokes it for the five tables above; a broader revoke is worth planning.
- `handle_new_user()` and `touch_conversation_on_message()` are trigger functions that anon can call through `/rest/v1/rpc`. Migration revokes EXECUTE.
- 5 functions have a mutable `search_path` (`community_bump_*`, `update_updated_at`, `is_client_request`). All are SECURITY INVOKER. Migration sets it.
- `/api/notify-subscribers` is public and has no rate limit or de-duplication: within 10 minutes of a new request, repeated calls re-send the email to all subscribers. Proposed fix: add a `notified_at` column on the request tables and mark it in the route (needs a schema change).
- Advisor: `community_posts_public` is a SECURITY DEFINER view (intentional per CLAUDE.md; it hides `user_id`).
- Advisor: leaked password protection disabled; Postgres has pending security patches.
- npm: 1 high (`postcss`) and 1 moderate (`next`) remain; both only resolve with Next 16 (major). Report only. Also `@tailwindcss/typography` moderate.
### Low
- `upload-profile-picture` returns `error.message` in `detail`, and builds the object key from the user-supplied file extension. Proposed fix: derive the extension from the MIME type.
- `check_user_status(uid)` is callable by anon and reveals whether a user id is deleted.
- Advisor `rls_enabled_no_policy` on 9 tables: expected (`community_*`, `chat_notification_state` are server-only).
- `daily-digest` has a "TEMP" 30-day window instead of 24 hours.
- API routes log request payloads on invalid NicePay webhooks (`console.error('...', payload)`); NicePay is legacy.

The column-grant and policy queries from section 1 cover the same ground for `student_jobs`, `hagwon_requests` and `teachers`. Note `payments`, `payment_request` and `newsletter_subscriptions` have no anon SELECT policy, so they cannot return rows, but `expedite_payments`, `purchases`, `payouts` can be read or written by anon per their policies (not probed).
