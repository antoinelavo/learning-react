## Weak points (not fixed)
### High
- `pages/profile/[name].js` (unchanged from last week): both not-found branches return `{ notFound: true }` without `revalidate`, so a profile visited before the teacher is approved stays 404 until the next deploy. `/profile/슈이` is 200 again only because a deploy cleared the cache. Suggested fix: return `{ notFound: true, revalidate: 60 }` in both branches. Not fixed here (ISR/data-fetching logic).
- `/find` (`components/TeacherCard.js`): the page loads every teacher's original R2 photo through a plain `<img>` (no resizing, no `loading="lazy"`), so PageSpeed measured a 94 MB mobile payload (single photos up to 5 MB, est. 8.8 MB savings from image delivery alone). Score fell from 79 to 66, LCP 5.6 s. Suggested fix: add `loading="lazy"` and `decoding="async"`, and serve resized thumbnails (resize on upload in `app/api/upload-profile-picture`, or use `next/image` with the R2 domain in `images.remotePatterns`). Not fixed (performance change).
- Blog post descriptions and internal links: 21 posts still have a description outside 120–160 characters and/or fewer than 3 internal links (this week's count includes absolute `https://www.ibmaster.net/...` links). Suggested fix: continue next week, worst first (description length / internal links):

### Medium
- Live `robots.txt` (Cloudflare): the served file is now `public/robots.txt` prefixed by a "Cloudflare Managed content" block: content-signal comments, a separate `User-agent: *` group with `Content-Signal: search=yes,ai-train=no,use=reference` and `Allow: /`, and `Disallow: /` for ~30 AI/other crawlers (including `GoogleOther`, `Google-Extended`, `Baiduspider`, `ClaudeBot`, `GPTBot`). Google merges both `*` groups, so the private-page `Disallow`s still apply there, but crawlers that only read the first matching group (possibly Naver's Yeti) would see `Allow: /` and nothing else. Suggested fix: if unintended, turn off "Manage robots.txt" / AI-crawler blocking in the Cloudflare dashboard; if intended, confirm in Naver Search Advisor's robots.txt tester that `/admin`, `/dashboard` and the private community pages are still blocked.
