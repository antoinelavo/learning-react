## Weak points (not fixed)
### High
- `pages/profile/[name].js` (fifth week, now confirmed live): both not-found branches (lines 145 and 152) return `{ notFound: true }` without `revalidate`, so a cached 404 never expires until the next deploy. **`/profile/조규동` returns 404** (`x-vercel-cache: HIT`, `age: 68732`) even though the teacher is `approved`, not a test account, and listed in the sitemap. Their profile was updated on 2026-11-18, so it was probably briefly un-approved, and a visit during that window cached the 404. `김영채 화학 튜터` (now `pending`) will hit the same problem once re-approved. Suggested fix: return `{ notFound: true, revalidate: 60 }` in both branches, then redeploy (or revalidate the path) to clear `조규동`'s cached 404. Not fixed here because it changes ISR/data-fetching logic.
