- **Vercel production deploys failing since 2026-11-19.** The Vercel status is `failure` on `9e3d0dd` (#86) and on the current `main` head `a569751` (#88). The last successful deploy was `5103c6d` on 2026-11-17. - **Teacher profiles returning cached 404s** (sixth week, now 6 profiles). Each is `approved`, not a test account, listed in the sitemap, and returns 404 with `x-vercel-cache: HIT`: `조규동` (last updated 2026-11-18), `김영채 화학 튜터` (2026-11-19), `JHC` (2026-11-24), `Solhee Lee` (2026-11-24), `김소희` (2026-11-25), `Olivia S` (2026-11-25). All were edited recently, which matches the pattern: an edit (or approval) briefly makes the profile non-approved, a visit in that window caches `{ notFound: true }`, and that 404 never expires because both not-found branches in `pages/profile/[name].js` (lines 171 and 178 after #87) have no `revalidate`. Newly approved profiles nobody visited earlier work (for example `IB44점여선생님` returns 200). Suggested fix: return `{ notFound: true, revalidate: 60 }` in both branches. A successful deploy (see above) will clear the current cached 404s, but they will come back without this change. Not fixed here because it changes ISR and data-fetching logic. #87 (merged) did not add it. On a re-check after #87 merged, `/profile/조규동` returned 200 (cache MISS), while `/profile/Olivia S` still returned a cached 404.
